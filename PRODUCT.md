# Product

## Register

product

## Users

Waymark serves software builders and AI-assisted development users who need a fast, local view of project state. They are usually working inside a real codebase, moving between tickets, decisions, context links, and agent handoffs without wanting another hosted project-management system.

## Product Purpose

Waymark is a local-first desktop cockpit for software project memory. It keeps durable state in readable Markdown and YAML, then provides a focused UI for scanning current work, managing local tickets, capturing ideas and decisions, referencing AI threads, and generating Codex or Claude-ready handoff prompts. Success means a user can confidently answer what state a project is in and start the next implementation thread with less manual context gathering.

## Brand Personality

Quiet, precise, trustworthy. Waymark should feel like an operational tool with strong taste: dense enough for repeated daily use, calm enough to think in, and explicit about every write it performs.

## Anti-references

- Marketing-page structure, oversized hero sections, and decorative card grids.
- Notebook-first interfaces where durable project state is hidden inside prose.
- Hosted-service assumptions such as accounts, cloud sync, telemetry, or external API dependencies.
- Noisy AI surfaces that make every field feel token-consuming or imply hidden automation.
- Vague controls that hide what will be filtered, written, copied, or sent.

## Design Principles

- File-native confidence: project memory should remain readable and inspectable outside the app.
- Cockpit over notebook: prioritize scan speed, rows, lists, compact panels, and clear selected states.
- Human-controlled AI: AI can prepare drafts and recommendations, but the user reviews and saves.
- Explicit writes: every project-memory mutation must be visible, intentional, and undoable where supported.
- Context before handoff: make readiness gaps, linked files, decisions, thread references, and prompt context explainable.

## Accessibility & Inclusion

Waymark should preserve keyboard access, visible focus states, clear labels, readable dense typography, and state cues that do not rely on color alone. Motion should be restrained and tied to state changes. Copy should explain consequential actions without forcing users through hidden or modal-heavy flows.
