# Promote guided repo onboarding into MVP scope

Waymark should give users an explicit way to attach local repositories to a project and create the first useful project-memory layer around them. This is promoted into MVP scope because onboarding a real repo is part of making the cockpit useful on day one, not a later convenience.

The promoted shape is guided and review-gated. Waymark may add user-picked repo references, scaffold missing Waymark memory files, and ask Codex to draft summaries, initial tickets, decisions, handoff context, or repo agent instructions. The user must preview and accept generated files or records before Waymark writes them.

This does not promote broad importers, hosted service integrations, automatic repo indexing, whole-repo prompt stuffing, or direct Codex file mutation. Markdown and YAML remain canonical, and Codex remains optional.
